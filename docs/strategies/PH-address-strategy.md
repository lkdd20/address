# PH 菲律宾地址生成策略

| 项目 | 核心内容 |
|---|---|
| 主源 | Geofabrik `philippines`；PHLPost Zip Code Locator |
| 既有门牌级格式 / 邮编 | `<house> <street>, <barangay>, <city/municipality>, <province> <postcode>, PH`；格式门禁 4 位数字。源记录缺邮编时，仅允许按 PHLPost 的省份 + 城市/市镇唯一匹配补全；无法唯一匹配时地址不发布，不按邻近地址补齐（2026-10-26）；来源行政冲突仍拒绝。 |
| 行政区 | 保留 OSM `addr:barangay` 并映射为最低行政层；PSA PSGC 只做省、市镇、Barangay 名称核验，不生成住宅门牌；对不上目录的 admin1（Eastern Manila District、Region XII、North Cotabato 等）按坐标改为一级大区目录名称（administrative-names-v19） |
| 住宅子集证据 | OSM 住宅建筑标签；barangay 名称不能证明住宅。住宅证据必须来自明确建筑/用途字段，不能由地址存在推断 |
| 街道级格式 | `<street>, <barangay>, <city/municipality>, <province>, PH`；`matchLevel=street`，门牌、楼栋、室号为空；可唯一确定的来源邮编保留，否则留空。 |
| 街道去重 / 验证 | 国家 + 规范行政层级 + 街道名，同一路段不同坐标、邮编或来源 ID 不增加条数；行政字段不使用最近目录点推断。 |
| 同步方式 | 自动初始化一次；显式启用来源探测后，以 HEAD 检查 OSM PBF，并从 PHLPost sitemap 读取 `lastmod`。元数据不变时不下载正文；每个来源版本只构建一次，无增长时标记来源耗尽 |
| 既有门牌来源验证 / 排除 | PHLPost 只核验四位邮编；城市或省级字段缺失时不按邮编反推行政区。PSA PSGC 只提供行政目录，不用于补造门牌。 |
| 策略版本 / 状态 / 更新 | 1.17 / 邮编元数据轻量探测 + 单版本单次构建 + 有限失败暂停 + 街道契约 street-v1 + address-structure-v1 + administrative-names-v19 / 2026-10-20 |
共用规则（翻译、发布、生成、同步框架和结构门禁）见 [README.md](README.md)；本文件只记录本国差异。

- 上游目录约 74% 的城市挂错省份（如宿务城镇挂在 Bataan 下），按 COD-AB 省界逐一核定后写入 `server/database/catalog-city-regions.json`。admin1 所属大区与 Overture 一级行政区多边形不一致时，按目录邮编改为多边形大区内的省份，给不出时改为大区；同一大区内邮编与最近目录城市一致指向另一省时改为该省。
- 默认国家完成数量下限 10,000；大区、省、市县、Barangay 单来源均衡采样上限 2,500/500/150/40，后台可覆盖；国家总量不是发布上限，行政区划与邮编目录保持完整。

- OSM 独立地址点仅在精确落入明确住宅建筑面时获得住宅用途证据；不使用附近建筑、同街道或邻近坐标推断。
- 临时失败最多连续重试 8 次，随后暂停到下一探测窗口；单任务和外部导出进程均有硬超时，禁止长期占用队列。

## Google 真实地址补全

- 数据源：既有 Geofabrik OSM 住宅建筑、来源地址及命名道路种子；Google 返回实际道路、门牌、行政区与坐标，住宅用途只能来自独立 OSM 建筑证据。
- 调度：优先查询官方目录中零覆盖、未达最低数量和一级/二级数量不足的节点。目录中心点仅用于种子排序；最终行政归属仍由 Google 响应通过官方目录与坐标门禁后确定。所有目录城市统一计入最低行政层分母，不因分支深度不同而遗漏。
- 真实字段：Google Geocoding v4 的门牌、道路、行政区、可唯一确认的邮编、WGS84 坐标和 Place ID；同响应补齐只接受国家及已有父级一致、候选值唯一的行政字段。无生成地址字段。
- 同步：配置 Google Geocoding 凭据后按有界批次执行。checkpoint 按适配器版本、上游 PBF 版本和提取策略隔离；连续批次没有总量、覆盖或节点进展时标记来源已达上限，凭据或额度等待不会误判为耗尽。
- 门禁：逐条检查同响应的 route/street_address/premise/subpremise，国家、行政层、本国语言和种子几何均须匹配；坐标位于住宅 polygon 内或距种子点不超过 15 米。street 没有门牌/住宅证据；真实门牌保留，未知或歧义邮编须经推断唯一确定，否则不发布。
- 去重：门牌保留来源稳定身份；街道按国家、规范行政层与道路名去重，恢复时从已有规范化输出重建去重集合。所有实际 HTTP dispatch 计入预算，失败与 Key 轮换不能绕过额度。
- 适配器版本：`osm-address-street-google-geocoding-v9`；2026-09-08。

## 既有来源街道提取（2026-09-08）

- Geofabrik `g70-streets` 提取来源命名道路及已有门牌，保留真实行政字段；道路点位于原始线几何，按国家/行政层/道路去重，不从最近目录点补行政区。街道楼栋、单元和住宅证据为空，邮编须经导入后推断唯一确定，否则不发布（2026-10-26）；非住宅门牌保留但不获得住宅用途。

## 城市级契约与行政边界补全（2026-10-01）

- 必填行政层级降为“一级行政区（如适用）+ 城市”，district 改为可选：来源有值时保留，缺失时用官方/开放行政边界按坐标补全，补不到则留空，不再整条拒绝。街道和门牌仍必须来自来源，坐标、国家边界、语言和邮编门禁不变。
- 边界数据：NAMRIA/PSA COD-AB（OCHA HDX，CC BY-IGO）：ADM4 Barangay → district，ADM3 市/镇 → locality。
- 补全规则：只填补来源为空的 district，或与城市同名的 district；来源已有值不覆盖；坐标不落在任何边界内则不补；城市只在来源与目录补全后仍为空时用边界补。边界名称直接取自数据集，不翻译反推。
- Geofabrik、Overture、OpenAddresses 三类批量来源的能力指纹附加本国边界版本，仅这些来源因能力变化重新执行一次；其他来源的耗尽状态不受影响。

## Google 结果与城市级字段（2026-10-02）

- 适配器版本 `osm-address-street-google-geocoding-v10-city-level`（Mappls 为 `osm-source-address-street-mappls-reverse-v5-city-level`）。
- Google 结果落在 OSM 种子建筑外或 15 米外时，不再以 `geometry_mismatch` 丢弃：作为 Google 自身坐标的真实地址发布，`property_type=unknown`，不借用 OSM 住宅证据；只有落在种子建筑内的结果才标记住宅。
- 住宅结果只要求门牌、道路及城市级行政字段（大区/省、城市）；区县和邮编来源有值时保留，缺失、冲突或格式无效时留空，不淘汰地址。
- 通用规则：中国以外无法验证的邮编须经推断唯一确定，否则地址不发布（2026-10-26），本地数字（阿拉伯-印度、泰文）先转为 ASCII。

- 单次上限（capacity-20261003）：google-residential-enrichment（1 个分片）：API 来源，上限保持 10000，不增加付费或额度消耗；geofabrik（1 个分片）：单次上限 200,000。

- 来源缺少邮编时按顺序推断，且只在结果唯一时填写，冲突一律留空：
  1. GeoNames 邮编目录中同一一级行政区下该城市或区县只对应一个邮编，且目录坐标在约 30 km 内（CC BY 4.0）；
  2. 同一城市约 1 km 范围内至少 3 条来源自带邮编的地址邮编一致（推断出的邮编不参与投票）。

## 目录本地名核验（2026-10-11）

- 目录本地名修正：省级 0 条、城市 1917 条（已存地址由 catalog-native-addresses-v2 一次性改写）。

- 一级行政区多边形：目录层级与多边形不一致，仅排除境外坐标，不改写来源区域。
