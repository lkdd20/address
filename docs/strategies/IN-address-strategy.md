# IN 印度地址生成策略

| 项目 | 核心内容 |
|---|---|
| 数据源 | Geofabrik `india`；Mappls Reverse Geocoding；Google Geocoding 补全 |
| 既有门牌级格式 / 邮编 | `<house>, <street/locality>, <city>, <state> <PIN>, IN`；公寓/楼层缺失不补；源记录；格式门禁 6 位数字（允许中间空格）。只清洗格式，不创造或按邻近地址补齐 |
| 行政区 | 源字段与 catalog；Census of India/官方州界作为候选核验。行政层级必须与坐标反查一致；冲突时保留源值在隔离区并拒绝发布 |
| 住宅子集证据 | OSM 明确住宅建筑标签。Mappls 与 Google 只补全地址字段，不单独证明住宅；PIN 只代表邮区 |
| 坐标 / 去重 | WGS84 经纬度并通过印度边界门禁；同一批次按规范化地址 canonical hash 去重，补全来源按 OSM 建筑 ID 去重 |
| 街道级格式 | `<street>, <district>, <city>, <state>, IN`；`matchLevel=street`，门牌、楼栋、室号为空；可唯一确定的来源邮编保留，否则留空。 |
| 街道去重 / 验证 | 国家 + 规范行政层级 + 街道名，同一路段不同坐标、邮编或来源 ID 不增加条数；行政字段不使用最近目录点推断。 |
| 同步方式 / 频率 | Geofabrik 版本检查；Mappls 与 Google 使用可恢复 checkpoint、额度冷却和多 Key 轮换。新快照通过门禁后原子切换，失败保留上一 active 快照 |
| 既有门牌来源验证 / 排除 | 仅以英文（拉丁字母）发布，天城文、泰米尔文等本地文字片段在导入时删除；街道、城市、一级行政区或门牌只剩本地文字时整条丢弃，不做机器翻译替代原文。行政层级冲突时丢弃。India Post PIN Directory 只核验邮编、行政区和邮局；DIGIPIN 不是邮政地址；GOBS 缺完整门牌、街道、邮编和可靠住宅用途 |
| 策略版本 / 状态 / 更新 | 1.16 / 英文单语言（india-english-v1） + 街道契约 street-v1 + address-structure-v1 + administrative-names-v19 / 2026-10-20 |
共用规则（翻译、发布、生成、同步框架和结构门禁）见 [README.md](README.md)；本文件只记录本国差异。

- 默认国家完成数量下限 20,000；邦/领地、县市、地区单来源均衡采样上限 1,800/300/70，后台可覆盖；国家总量不是发布上限，行政区划与邮编目录保持完整。

- OSM 独立地址点仅在精确落入明确住宅建筑面时获得住宅用途证据；不使用附近建筑、同街道或邻近坐标推断。
- 官方依据：<https://www.data.gov.in/resource/all-india-pincode-directory-till-last-month>、<https://www.indiapost.gov.in/digipin>。

## Mappls 真实地址补全

- OSM 提供来源门牌或命名道路及实际几何；仅独立住宅建筑提供住宅证据。无名道路不作为种子。
- Mappls Reverse Geocoding 提供邦、城市/村、district、6 位 PIN 和返回坐标；返回国家必须为印度，坐标必须落在种子 polygon 内或距种子点不超过 15 米；已有行政字段与道路不得冲突，冲突行政组合拒绝。
- 门牌和道路始终使用 OSM 原始字段，不从 Mappls 格式化文本拆分或推断；Mappls 不作为住宅证据。
- 进度按适配器版本、Geofabrik PBF 版本与提取策略持久化；额度恢复后自动续跑，完成后自动清理断点。连续批次没有总量、覆盖或节点进展时，当前来源指纹标记已达上限。
- 适配器版本：`osm-source-address-street-mappls-reverse-v4`；2026-09-08。

- 发布校验与数量口径（2026-09-06）：必填字段和中英文版本未就绪的记录不计入生成、国家总量或行政覆盖。历史记录自动复核，淘汰后刷新来源数量、生成索引和覆盖统计；索引切换在同一事务完成。

## Google 真实地址补全

- 数据源：既有 Geofabrik OSM 住宅建筑、来源地址及命名道路种子；Google 返回实际道路、门牌、行政区与坐标，住宅用途只能来自独立 OSM 建筑证据。
- 调度：优先查询官方目录中零覆盖、未达最低数量和一级/二级数量不足的节点。目录中心点仅用于种子排序；最终行政归属仍由 Google 响应通过官方目录与坐标门禁后确定。
- 真实字段：Google Geocoding v4 的门牌、道路、行政区、可唯一确认的邮编、WGS84 坐标和 Place ID；同响应补齐只接受国家及已有父级一致、候选值唯一的行政字段。无生成地址字段。
- 同步：配置 Google Geocoding 凭据后按有界批次执行。checkpoint 按适配器版本、上游 PBF 版本和提取策略隔离；缓存清理保留未完成状态并在完成后自动删除。连续批次没有总量、覆盖或节点进展时标记来源已达上限；缺 Key、额度冷却或短时限流不会误判为耗尽。
- 门禁：逐条检查同响应的 route/street_address/premise/subpremise，国家、行政层、本国语言和种子几何均须匹配；坐标位于住宅 polygon 内或距种子点不超过 15 米。street 没有门牌/住宅证据；真实门牌保留，未知或歧义邮编须经推断唯一确定，否则不发布。
- 去重：门牌保留来源稳定身份；街道按国家、规范行政层与道路名去重，恢复时从已有规范化输出重建去重集合。所有实际 HTTP dispatch 计入预算，失败与 Key 轮换不能绕过额度。
- 适配器版本：`osm-address-street-google-geocoding-v9`；2026-09-08。

## 既有来源街道提取（2026-09-08）

- Geofabrik `g70-streets` 提取来源命名道路及已有门牌，保留真实行政字段；道路点位于原始线几何，按国家/行政层/道路去重，不从最近目录点补行政区。街道楼栋、单元和住宅证据为空，邮编须经导入后推断唯一确定，否则不发布（2026-10-26）；非住宅门牌保留但不获得住宅用途。

## 城市级契约与行政边界补全（2026-10-01）

- 必填行政层级降为“一级行政区（如适用）+ 城市”，district 改为可选：来源有值时保留，缺失时用官方/开放行政边界按坐标补全，补不到则留空，不再整条拒绝。街道和门牌仍必须来自来源，坐标、国家边界、语言和邮编门禁不变。
- 边界数据：Overture Maps divisions（ODbL）：`neighborhood`/`macrohood` → district，`locality` → locality，优先英文名。
- 补全规则：只填补来源为空的 district，或与城市同名的 district；来源已有值不覆盖；坐标不落在任何边界内则不补；城市只在来源与目录补全后仍为空时用边界补。边界名称直接取自数据集，不翻译反推。
- Geofabrik、Overture、OpenAddresses 三类批量来源的能力指纹附加本国边界版本，仅这些来源因能力变化重新执行一次；其他来源的耗尽状态不受影响。

## Google 结果与城市级字段（2026-10-02）

- 适配器版本 `osm-address-street-google-geocoding-v10-city-level`（Mappls 为 `osm-source-address-street-mappls-reverse-v5-city-level`）。
- Google 结果落在 OSM 种子建筑外或 15 米外时，不再以 `geometry_mismatch` 丢弃：作为 Google 自身坐标的真实地址发布，`property_type=unknown`，不借用 OSM 住宅证据；只有落在种子建筑内的结果才标记住宅。
- 住宅结果只要求门牌、道路及城市级行政字段（州、城市）；区县和邮编来源有值时保留，缺失、冲突或格式无效时留空，不淘汰地址。
- 通用规则：中国以外无法验证的邮编须经推断唯一确定，否则地址不发布（2026-10-26），本地数字（阿拉伯-印度、泰文）先转为 ASCII。

- 单次上限（capacity-20261003）：google-residential-enrichment（1 个分片）：API 来源，上限保持 10000，不增加付费或额度消耗；geofabrik（1 个分片）：单次上限 200,000。

- 来源缺少邮编时按顺序推断，且只在结果唯一时填写，冲突一律留空：
  1. GeoNames 邮编目录中同一一级行政区下该城市或区县只对应一个邮编，且目录坐标在约 30 km 内（CC BY 4.0）；
  2. 同一城市约 1 km 范围内至少 3 条来源自带邮编的地址邮编一致（推断出的邮编不参与投票）。

## 目录本地名核验（2026-10-11）

- 目录本地名修正：省级 36 条、城市 4198 条（已存地址由 catalog-native-addresses-v2 一次性改写）。

## 英文单语言（2026-10-11）

- 印度地址的原文语言为英文（`native_language=en`），原文与英文版本相同；中文版本照常翻译。
- 导入：街道、门牌、楼名、单元、区县、城市、邮政城市、一级行政区中的非拉丁文字片段（含本地数字，转为阿拉伯数字）被删除，括号、分隔符残留一并清理（如 `சென்னை - Chennai` → `Chennai`）。街道、城市、一级行政区或门牌（门牌级）只剩本地文字时整条拒绝；楼名、单元、区县、邮政城市只剩本地文字时该字段留空。
- 门禁：质量规则 `non_latin_text` 拒绝任一字段含非拉丁文字的印度地址，作用于导入、发布、读取与线上抽检（`quality_non_latin_text`）。
- 已存地址：sync 启动时一次性修复（修订 `india-english-v1`，进度保存在 `translation_backfill_progress`）。字段已有合格英文译名时用译名替换本地文字，否则删除本地文字片段；核心字段为空的地址以 `publication-validation:india-english-v1:<时间>` 撤下；修复后与已有地址重复的删除。重建原文、英文地址字符串，必要时重建中文串，更新去重键并刷新生成索引；全部印度地址的原文语言改为 `en`。

- 一级行政区多边形：纠正与坐标冲突或无法识别的来源区域，并排除境外坐标。
