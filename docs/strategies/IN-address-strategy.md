# IN 印度地址生成策略

| 项目 | 核心内容 |
|---|---|
| 数据源 | Geofabrik `india`；Mappls Reverse Geocoding；Google Geocoding 补全 |
| 格式 / 邮编 | `<house>, <street/locality>, <city>, <state> <PIN>, IN`；公寓/楼层缺失不补；源记录；格式门禁 6 位数字（允许中间空格）。只清洗格式，不创造或按邻近地址补齐 |
| 行政区 | 源字段与 catalog；Census of India/官方州界作为候选核验。行政层级必须与坐标反查一致；冲突时保留源值在隔离区并拒绝发布 |
| 住宅证据 | OSM 明确住宅建筑标签。Mappls 与 Google 只补全地址字段，不单独证明住宅；PIN 只代表邮区 |
| 坐标 / 去重 | WGS84 经纬度并通过印度边界门禁；同一批次按规范化地址 canonical hash 去重，补全来源按 OSM 建筑 ID 去重 |
| 发布门禁 | 质量高于数量。仅发布 E3：地址存在与独立住宅用途证据同时成立；本国格式规定的必填组件缺一即淘汰，字段冲突拒绝合并；只允许可逆、可验证的格式规范化。 |
| 同步方式 / 频率 | Geofabrik 版本检查；Mappls 与 Google 使用可恢复 checkpoint、额度冷却和多 Key 轮换。新快照通过门禁后原子切换，失败保留上一 active 快照 |
| 验证 / 排除 | 多语种脚本与行政层级冲突时丢弃，不做机器翻译替代原文。India Post PIN Directory 只核验邮编、行政区和邮局；DIGIPIN 不是邮政地址；GOBS 缺完整门牌、街道、邮编和可靠住宅用途 |
| 策略版本 / 状态 / 更新 | 1.6 / Mappls Reverse 补全适配器已通过真实接口探测 / 2026-08-24 |

- 默认 active 地址上限 20,000；邦/领地、县市、地区单节点上限 1,800/300/70，后台可覆盖；只裁剪地址记录，行政区划与邮编目录保持完整。

- OSM 独立地址点仅在精确落入明确住宅建筑面时获得住宅用途证据；不使用附近建筑、同街道或邻近坐标推断。
- 官方依据：<https://www.data.gov.in/resource/all-india-pincode-directory-till-last-month>、<https://www.indiapost.gov.in/digipin>。


默认同步生命周期为自动初始化一次；未完成的额度或 checkpoint 任务自动续跑，完整扫描或来源耗尽后停止，不按日/月重复执行。只有来源、上游版本、严格提取能力变化或管理员明确刷新才重新运行；周期元数据探测仅在显式启用时执行。

统一证据等级、许可、配额与 VPS 边界见 [数据源与自动同步方案](../data-sources.md)。策略变化时同步更新本文件、实现与测试。

## Mappls 住宅地址补全

- OSM 提供明确住宅建筑、建筑 ID、polygon、门牌和道路；缺少任一项的种子不调用 Mappls。
- Mappls Reverse Geocoding 提供邦、城市/村、district、6 位 PIN 和返回坐标；返回国家必须为印度，坐标必须落在住宅 polygon 内或距内部点不超过 15 米。
- 门牌和道路始终使用 OSM 原始字段，不从 Mappls 格式化文本拆分或推断；Mappls 不作为住宅证据。
- 进度按适配器版本、Geofabrik PBF 版本与提取策略持久化；额度恢复后自动续跑，完成后自动清理断点。连续批次没有总量、覆盖或节点进展时，当前来源指纹标记已达上限。
- 适配器版本：`osm-source-address-mappls-reverse-v3`；2026-08-24。
## 覆盖与保留

- 官方行政区目录定义覆盖分母；只有关联到官方节点的严格住宅地址计入分子。
- 每个有合格数据的最低行政区先满足每节点、省市和单节点目标，再轮询分配额外记录；国家总量是完成下限，节点规则可推动总量继续增长，来源或分片容量仍是技术硬限制。
- 每次国家快照发布后自动重建住宅覆盖；生成器只展示至少有 1 条可发布住宅地址的官方区域。


## 运行时随机生成

- 公开普通生成直接在 PostgreSQL 完整合格范围选择：支持连续生成序号的未筛选国家池按序号等概率选择，筛选范围使用有界循环索引窗口；不使用固定子集或固定顺序。
- 每次按 seed 在有界候选窗口内执行独立偏移，再按主键读取完整地址与证据；API 不把完整地址池加载到进程内存，也不执行全表随机排序。
- 未传入 seed 时由服务器为每个请求生成新 UUID；相同显式 seed 在同一数据库快照中可复现。数据库提交后，新 worker 快照全部就绪才原子替换旧快照。


## Google 住宅地址补全

- 数据源：Geofabrik OSM 明确标记为住宅的建筑面作为住宅证据；Google Geocoding 只反向补全地址字段，不单独证明住宅。
- 调度：优先查询官方目录中零覆盖、未达最低数量和一级/二级数量不足的节点。目录中心点仅用于种子排序；最终行政归属仍由 Google 响应通过官方目录与坐标门禁后确定。
- 真实字段：Google Geocoding v4 返回的门牌、道路、行政区、邮编、WGS84 坐标和 Place ID；同一次反向响应中同国家的邮编和行政结果可补全街道结果缺失的层级。OSM 返回建筑 ID、住宅建筑分类和 polygon。生成字段：无。
- 同步：配置 Google Geocoding 凭据后按有界批次执行。checkpoint 按适配器版本、上游 PBF 版本和提取策略隔离；缓存清理保留未完成状态并在完成后自动删除。连续批次没有总量、覆盖或节点进展时标记来源已达上限；缺 Key、额度冷却或短时限流不会误判为耗尽。
- 门禁：只接受正确国家、完整必填层级、`street_address/premise/subpremise`、高精度位置且坐标落在住宅 polygon 内或距内部点不超过 15 米的结果；核心字段使用本国语言。
- 去重：以 OSM 建筑 ID + Google Place ID 作为来源记录 ID，再执行统一 canonical hash 去重。完整扫描无总量、覆盖或节点进展后，当前来源能力指纹持久标记已达上限。
- 适配器版本：`osm-explicit-residential-google-geocoding-v8`；2026-08-19。
