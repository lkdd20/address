# MX 墨西哥地址生成策略

| 项目 | 核心内容 |
|---|---|
| 主源 | INEGI 全国地址框架原始 SHP/DBF；Digital Guard 保全包仅作可复现下载入口；OpenAddresses 同源标准化包只补充州/城市名称，不提供住宅证据 |
| 格式 / 邮编 | `<street> <house>, <colonia>, <municipio>, <estado>, <CP>, MX`；缺失字段留空；源记录；格式门禁 5 位数字。只清洗格式，不创造或按邻近地址补齐 |
| 行政区 | INEGI Marco Geoestadístico/municipios 作为候选交叉核验；Overture `address_levels` 完整保留并确定性映射州、市镇和最细来源层级。行政层级必须与坐标反查一致；冲突时保留源值在隔离区并拒绝发布 |
| 住宅证据 | 原始记录必须满足 `TIPODOM=VIVIENDA`；商业/政府/学校等黑名单剔除。住宅用途直接来自 INEGI 字段，不由地址存在或邻近建筑推断 |
| 真实字段 / 生成字段 | INEGI 门牌、道路、colonia、municipio、estado、邮编、坐标和 `TIPODOM` 均为来源字段；同源标准化包只映射名称。生成字段：无 |
| 坐标 / 去重 | INEGI 坐标统一为 WGS84 并通过墨西哥边界门禁；按来源 ID 和规范化地址 canonical hash 去重 |
| 发布门禁 | 质量高于数量。仅发布 E3：地址存在与独立住宅用途证据同时成立；本国格式规定的必填组件缺一即淘汰，字段冲突拒绝合并；只允许可逆、可验证的格式规范化。 |
| 同步方式 | 自动初始化一次；完整扫描或来源耗尽后停止。显式来源探测发现 INEGI 包版本或提取能力变化时才构建新快照 |
| 验证 / 排除 | 仅保留 `VIVIENDA` 且真实门牌、街道、住区、5 位非零邮编和合法坐标完整的记录；`SN`、`NINGUNO`、`00000` 全部淘汰。 |
| 策略版本 / 状态 / 更新 | 1.5 / INEGI 直接住宅用途 + 多规则完成下限 / 2026-08-24 |

- 默认 active 地址上限 20,000；州、市镇、地区单节点上限 2,000/300/70，后台可覆盖；只裁剪地址记录，行政区划与邮编目录保持完整。
- 原始 ITRF92 Lambert 坐标按源投影参数转换为 WGS84，并与同源标准化坐标精确匹配；原始门牌、街道、住区和邮编优先，不接受标准化包覆盖原始邮编。
- 首次严格快照只要存在合格记录即可发布；后续快照仍执行数量与行政覆盖防回退门禁。


默认同步生命周期为自动初始化一次；未完成的额度或 checkpoint 任务自动续跑，完整扫描或来源耗尽后停止，不按日/月重复执行。只有来源、上游版本、严格提取能力变化或管理员明确刷新才重新运行；周期元数据探测仅在显式启用时执行。

统一证据等级、许可、配额与 VPS 边界见 [数据源与自动同步方案](../data-sources.md)。策略变化时同步更新本文件、实现与测试。
## 覆盖与保留

- 官方行政区目录定义覆盖分母；只有关联到官方节点的严格住宅地址计入分子。
- 每个有合格数据的最低行政区先满足每节点、省市和单节点目标，再轮询分配额外记录；国家总量是完成下限，节点规则可推动总量继续增长，来源或分片容量仍是技术硬限制。
- 每次国家快照发布后自动重建住宅覆盖；生成器只展示至少有 1 条可发布住宅地址的官方区域。


## 运行时随机生成

- 公开普通生成直接在 PostgreSQL 完整合格范围选择：支持连续生成序号的未筛选国家池按序号等概率选择，筛选范围使用有界循环索引窗口；不使用固定子集或固定顺序。
- 每次按 seed 在有界候选窗口内执行独立偏移，再按主键读取完整地址与证据；API 不把完整地址池加载到进程内存，也不执行全表随机排序。
- 未传入 seed 时由服务器为每个请求生成新 UUID；相同显式 seed 在同一数据库快照中可复现。数据库提交后，新 worker 快照全部就绪才原子替换旧快照。
